## Current gate implementation

The service runner uses the nonzero per-subscope `break` thresholds in `tests/ResearchTrack.<Service>.MutationTests/configs/*.json`. These configurations, rather than the older top-level `stryker-config.json` files, govern runner execution.

The summary script expects aggregate floors in `config/testing/mutation-policy.json`, but that file is absent in this checkout. The recorded aggregate floors above therefore cannot be described as currently configured or enforced. When the file is absent, the summary generator loads an empty policy and displays `N/A` gates. With `--enforce`, any gate that is not `PASS`, including `N/A`, is treated as a failure.

The `all` runner invokes summary generation with `--enforce` when Python 3 is available. A final full run cannot pass its weighted gates without a valid aggregate policy. Without Python 3, the runner warns and skips the summary and weighted evaluation entirely. This documentation update does not create or change policy or runner behavior.

## Score calculation

The authoritative score comes from actual counts generated by [mutation-summary.py](../../../scripts/mutation-summary.py):

```text
mutation score = (Killed + Timeout) /
                 (Killed + Timeout + Survived + No coverage)
```

Multiply by 100 for a percentage. Sum the counts across subscopes or services before calculating the aggregate; never average percentages. Keep `Killed`, `Survived`, `Timeout`, `No coverage`, `Ignored`, and `Compile error` visible separately. Ignored and compile-error mutants are excluded from the denominator. Historical records that show only killed/survived counts do not establish whether timeout or no-coverage counts were zero; use original reports for full verification.

## Threshold rationale

Regression floors sit below measured baselines to detect meaningful losses of test effectiveness without requiring equivalent or low-value mutants to be killed. Stryker instrumentation can also produce compile errors. Strengthen tests for observable business behavior and document remaining survivors rather than broadening exclusions to chase a score.

## Final evidence

Run `bash ./scripts/mutation-baseline.sh all` as described in the [runbook](runbook.md). Final evidence requires passing normal suites and dedicated harnesses, passing per-subscope Stryker thresholds, reports for every subscope, and passing weighted service/project gates against a configured policy. Review timeout and no-coverage results explicitly and retain HTML, JSON, Markdown, and the generated summary.

The portfolio began with deterministic rules and expanded into authorization, orchestration, workflow, webhook, synchronization, and state-transition logic. The service hardening records preserve the test improvements and intermediate measurements; newly generated reports establish the current result.
