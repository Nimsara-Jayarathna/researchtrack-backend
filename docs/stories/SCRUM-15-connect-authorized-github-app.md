# SCRUM-15 — Connect an authorized GitHub repository through the ResearchTrack GitHub App

## Scope and security boundary

SCRUM-15 connects a ResearchTrack project to repositories granted to the ResearchTrack GitHub App. The browser never receives the GitHub App private key, App JWT, installation access token, Client Secret, GitHub password, or PAT.

The direct flow is:

1. An authenticated Supervisor starts the flow for a Research Project.
2. GitHub Service verifies project-management permission and creates a 256-bit, one-time ResearchTrack state value. Only its SHA-256 hash and server-side project/user/return context are persisted.
3. The browser is redirected only to the server-generated GitHub App installation URL.
4. GitHub returns to the backend setup URL. The backend validates ResearchTrack state before using `installation_id`.
5. The candidate installation is bound atomically to the state and checked with the App identity.
6. The backend performs a short GitHub user-authorization/PKCE step and confirms that the GitHub user can access the exact pending installation. This follows GitHub's warning that a setup-URL `installation_id` must not be trusted by itself.
7. Only after that verification is the state consumed and the installation-backed access source persisted.
8. Repository discovery and confirmation use short-lived installation tokens server-side. Repository metadata is refreshed from GitHub by the stable numeric GitHub repository ID before linking.
9. Durable repository linking calls the existing `IInitialRepositorySyncRequester` handoff. SCRUM-15 does not introduce a second synchronization engine.

## GitHub App registration

Create or use the GitHub App dedicated to ResearchTrack. The GitHub App display name itself is not consumed by code. After registration, configure these values:

- **App slug**: copy the actual slug generated by GitHub into `GitHub__AppSlug`.
- **App ID**: copy the numeric App ID into `GitHub__AppId`.
- **Client ID**: copy the GitHub App Client ID into `GitHub__ClientId`.
- **Client Secret**: create a GitHub App client secret and provide it only to the backend as `GitHub__ClientSecret`.
- **Private key**: generate a GitHub App private key, store the PEM outside source control, and set `GitHub__PrivateKeyPath` to its backend-readable filesystem path.
- **Setup URL**: set this to the public ResearchTrack callback endpoint. For local direct-service development the example is `http://localhost:5103/api/github/access-source/install/callback`. In a deployed environment use the public HTTPS backend/gateway origin plus `/api/github/access-source/install/callback`.
- **Callback URL**: set the GitHub App OAuth callback URL to the same public callback endpoint. The backend explicitly starts the user-authorization leg after the setup callback.
- **Request user authorization (OAuth) during installation**: leave this disabled. ResearchTrack uses the Setup URL first, then explicitly starts the user authorization check so it can bind the returned installation to the existing ResearchTrack state.
- **Frontend return origin**: set `GitHub__FrontendReturnOrigin` to the ResearchTrack frontend origin only, for example `http://localhost:5173` locally or the production HTTPS frontend origin. Do not include a path, query, or fragment.
- **State expiry**: set `GitHub__StateExpiryMinutes` to a short value from 1–30 minutes; the committed example uses 10.

GitHub documentation:

- Setup URL: https://docs.github.com/apps/creating-github-apps/registering-a-github-app/about-the-setup-url
- User access token web flow / PKCE: https://docs.github.com/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app
- Installation access tokens: https://docs.github.com/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app

## Least-privilege permissions for SCRUM-15

For the code currently in this branch, configure repository permissions as follows:

- **Metadata: Read-only** — required for repository metadata/default-branch lookup by repository ID.

Repository selection is restricted by the repositories granted to the installation. The installation repository-list endpoint itself does not require a broader repository-content permission.

Do **not** grant Contents, Pull requests, Issues, Administration, Actions, or write permissions merely for SCRUM-15. No webhook is required by the current SCRUM-15 implementation.

## Backend configuration keys

Configure these in the GitHub Service environment only:

```text
GitHub__AppId
GitHub__AppSlug
GitHub__ClientId
GitHub__ClientSecret
GitHub__PrivateKeyPath
GitHub__SetupCallbackUrl
GitHub__FrontendReturnOrigin
GitHub__StateExpiryMinutes
```

Existing unrelated GitHub Service keys such as webhook/synchronization settings remain part of the wider service contract, but they are not required by SCRUM-15 unless their owning story is enabled.

Never create frontend `VITE_*` variables containing GitHub credentials.

## Secret handling

- Keep the real `.env` / `.env.local` files untracked.
- Never commit the GitHub App PEM private key.
- Do not print the private key, Client Secret, App JWT, GitHub user token, installation token, Authorization headers, or ResearchTrack state values.
- Installation tokens are created on demand and are not stored in ResearchTrack tables.
- GitHub user tokens exist only for the callback identity check and are not persisted.
- `installation_id` is an identifier, not a credential.

Missing required GitHub App configuration fails with a configuration-key-specific message such as `Required GitHub App configuration 'GitHub:AppId' ...`; configuration values are not included in the error.

## Manual real-GitHub QA

A real GitHub test is required after environment credentials and public callback URLs are configured:

1. Log in to ResearchTrack as a Supervisor who can manage the target Research Project.
2. Open the Research Project and its GitHub integration.
3. Choose **Connect GitHub**.
4. Confirm the browser is sent to the GitHub App installation page generated by the backend.
5. Grant the App access to a private test repository.
6. Return through the backend setup callback and complete the GitHub user-authorization check.
7. Confirm ResearchTrack returns to the original project and loads only repositories accessible to that installation.
8. Select exactly one repository and confirm the link.
9. Verify the stored numeric GitHub repository ID, owner/full name, canonical URL, and default branch against GitHub.
10. Verify the link persists after refreshing the project page and the synchronization status reflects the shared handoff.
11. Start again and cancel/deny at GitHub; confirm no new source/link appears.
12. Replay an already-used callback/state; confirm it fails.
13. Attempt the start/list/link operations as a user without project-management permission; confirm normal 401/403 behavior.
14. Remove the repository from the App installation after it was listed but before confirming; confirm the link is rejected.
15. Remove App access after linking and retry repository discovery; confirm a safe access/unavailable error instead of stale success.
